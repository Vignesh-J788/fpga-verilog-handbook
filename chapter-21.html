Counters & Shift Registers

Chapter 20 ended with a hint: T flip-flops "want to toggle," making them the natural building block for counters. This chapter builds real counters and shift registers — both genuinely everywhere in real digital systems.

📖 Beginner Level🕐 —🧩 7 sections

4-Bit Up Counter

A counter is just a register (a group of flip-flops, Chapter 20) that adds 1 to itself on every clock edge — nothing more exotic than that.

counter_up.v
module counter_up (
    input  wire clk, rst,
    output reg [3:0] count
);
    always @(posedge clk or posedge rst) begin
        if (rst)
            count <= 4'b0000;
        else
            count <= count + 1;   // automatically wraps: 15 + 1 = 0 (4-bit overflow, Chapter 16)
    end
endmodule

Note that count + 1 naturally wraps from 15 back to 0 — exactly the overflow behavior explored in Chapter 16's ripple-adder test, now happening automatically every 16 clock cycles.

Down Counter and Up/Down Counter

counter_down.v
module counter_down (
    input  wire clk, rst,
    output reg [3:0] count
);
    always @(posedge clk or posedge rst) begin
        if (rst)
            count <= 4'b1111;   // often starts at max value for a down counter
        else
            count <= count - 1;
    end
endmodule
updown_counter.v — one direction input picks the mode
module updown_counter (
    input  wire clk, rst, up_down,   // 1 = count up, 0 = count down
    output reg [3:0] count
);
    always @(posedge clk or posedge rst) begin
        if (rst)
            count <= 4'b0000;
        else if (up_down)
            count <= count + 1;
        else
            count <= count - 1;
    end
endmodule

A Parameterized Counter — Any Width, One File

Exactly like Chapter 11's ripple adder, a counter's width shouldn't be hardcoded if you can help it:

counter_param.v — works for ANY width N
module counter_param #(
    parameter N = 4
) (
    input  wire clk, rst,
    output reg [N-1:0] count
);
    always @(posedge clk or posedge rst) begin
        if (rst)
            count <= {N{1'b0}};   // replication operator: N zero-bits, whatever N is
        else
            count <= count + 1;
    end
endmodule

New trick: {N{1'b0}} is the replication operator — it repeats 1'b0 exactly N times, giving an all-zero reset value of exactly the right width no matter what N is set to.

Counter Testbench

counter_up_tb.v
module counter_up_tb;
    reg clk = 0, rst = 1;
    wire [3:0] count;

    counter_up uut (.clk(clk), .rst(rst), .count(count));

    always #5 clk = ~clk;

    initial begin
        #12 rst = 0;   // release reset after first edge, then let it free-run
        #200 $finish;  // let it run through more than one full wraparound (16 counts)
    end

    initial $monitor("t=%0t rst=%b count=%0d", $time, rst, count);
endmodule

Expected behavior: count stays at 0 while rst is high, then increments by 1 every clock edge — 0,1,2,...,14,15,0,1,... — cleanly wrapping back to 0 after 15, with no glitches, exactly matching the 4-bit overflow behavior from Chapter 16.

Shift Registers

A shift register is a chain of flip-flops where each one passes its value to the next on every clock edge — data "shifts" down the chain, one position per cycle. There are four common flavors, named by how data enters and leaves:

TypeMeaning
SISOSerial In, Serial Out — one bit in, one bit out, each clock cycle
SIPOSerial In, Parallel Out — bits enter one at a time, but the whole register can be read at once
PISOParallel In, Serial Out — load all bits at once, then shift them out one at a time
PIPOParallel In, Parallel Out — effectively just a plain multi-bit register
sipo_shift_reg.v — Serial-In, Parallel-Out, 4-bit
module sipo_shift_reg (
    input  wire clk, rst, serial_in,
    output reg [3:0] parallel_out
);
    always @(posedge clk or posedge rst) begin
        if (rst)
            parallel_out <= 4'b0000;
        else
            parallel_out <= {parallel_out[2:0], serial_in};  // shift left; new bit enters at LSB
    end
endmodule

The concatenation {parallel_out[2:0], serial_in} takes the lower 3 bits of the current value and appends the new incoming bit at the end — which is exactly a "shift left, insert at the bottom" operation, expressed in a single line.

sipo_shift_reg_tb.v
module sipo_shift_reg_tb;
    reg clk = 0, rst = 1, serial_in = 0;
    wire [3:0] parallel_out;

    sipo_shift_reg uut (.clk(clk), .rst(rst), .serial_in(serial_in), .parallel_out(parallel_out));

    always #5 clk = ~clk;

    initial begin
        #12 rst = 0;

        // feed in the bit pattern 1,0,1,1 one bit per clock edge
        serial_in = 1; #10;
        serial_in = 0; #10;
        serial_in = 1; #10;
        serial_in = 1; #10;

        #10 $finish;
    end

    initial $monitor("t=%0t serial_in=%b -> parallel_out=%b", $time, serial_in, parallel_out);
endmodule

After feeding in 1, 0, 1, 1 (one bit per clock edge), parallel_out should read 1011 — the exact bit sequence that went in, now sitting fully assembled and readable all at once, which is the entire point of a SIPO register.

Common Mistakes

  • Forgetting that count + 1 silently wraps on overflow — if your design actually needs to detect the wraparound (e.g., to trigger something else), you must explicitly check for it, like if (count == 4'b1111).
  • Off-by-one errors in shift direction — mixing up which end of the concatenation is the "new" bit versus the "shifted-out" bit.
  • Forgetting the reset value for a down counter should usually start at the maximum value, not 0.
  • Using = instead of <= in these clocked blocks (Chapter 13) — a persistent, easy-to-miss bug even for experienced beginners.

Summary

A counter is simply a register that adds (or subtracts) 1 from itself every clock edge, naturally wrapping around on overflow. A parameterized version reuses the same code for any bit width, using the replication operator ({N{1'b0}}) for a correctly-sized reset value. A shift register moves data one position per clock edge, with SISO/SIPO/PISO/PIPO describing how data enters and leaves — a SIPO register is built with one concise concatenation-based non-blocking assignment.

Interview Questions

  • What happens when a 4-bit up counter reaches 15 and increments again?
    It wraps around to 0 automatically, since the arithmetic overflow bit simply falls off the top of the 4-bit result, exactly like the ripple-adder overflow case from Chapter 16.
  • What is the difference between SIPO and PISO shift registers?
    SIPO (Serial-In, Parallel-Out) accepts data one bit per clock cycle but allows reading the entire register at once. PISO (Parallel-In, Serial-Out) loads all bits simultaneously but outputs them one bit at a time on subsequent clock cycles.
  • What does the replication operator {N{1'b0}} do?
    It repeats the value 1'b0 exactly N times, producing an all-zero bus of width N — useful for writing width-independent reset values in parameterized modules.

Viva Questions

  • What line of code performs the "shift" in sipo_shift_reg?
    parallel_out <= {parallel_out[2:0], serial_in};
  • Which input controls direction in updown_counter?
    up_down — 1 counts up, 0 counts down.
