Full Adder — All Three Styles

Chapter 11 already gave you the dataflow version (used inside the generate-based ripple adder). Here it is again alongside a structural version built from two half adders + an OR gate, exactly matching Chapter 4's diagram:

full_adder.v — dataflow (from Chapter 11)
module full_adder (
    input  wire a, b, cin,
    output wire sum, cout
);
    assign sum  = a ^ b ^ cin;
    assign cout = (a & b) | (b & cin) | (a & cin);
endmodule
full_adder_structural.v — built from 2 half adders (matches Chapter 4's diagram)
module full_adder_structural (
    input  wire a, b, cin,
    output wire sum, cout
);
    wire s1, c1, c2;

    half_adder ha1 (.a(a),  .b(b),   .sum(s1),  .carry(c1));
    half_adder ha2 (.a(s1), .b(cin), .sum(sum), .carry(c2));
    or (cout, c1, c2);

endmodule
full_adder_tb.v
module full_adder_tb;
    reg  a, b, cin;
    wire sum, cout;

    full_adder uut (.a(a), .b(b), .cin(cin), .sum(sum), .cout(cout));

    integer i;
    initial begin
        $dumpfile("full_adder.vcd"); $dumpvars(0, full_adder_tb);
        for (i = 0; i < 8; i = i + 1) begin
            {a, b, cin} = i[2:0];   // concatenation: sweep all 8 combos automatically
            #10;
        end
        $finish;
    end

    initial $monitor("t=%0t a=%b b=%b cin=%b -> sum=%b cout=%b", $time, a, b, cin, sum, cout);
endmodule
A neater trick worth noticing
{a, b, cin} = i[2:0]; uses the concatenation operator (Chapter 10) to pack all three inputs from a single loop counter i — automatically sweeping through all 8 combinations (000 through 111) without writing out 8 lines by hand. This scales far better than Chapter 15's manual approach as input counts grow.

Capstone: Verifying Chapter 11's Ripple-Carry Adder With Real Numbers

Now let's actually test the parameterized ripple_adder from Chapter 11 by adding real 4-bit numbers — including a case that overflows, to make sure Cout behaves correctly.

ripple_adder_tb.v
module ripple_adder_tb;
    reg [3:0] A, B;
    reg       Cin;
    wire [3:0] Sum;
    wire       Cout;

    ripple_adder #(.N(4)) uut (
        .A(A), .B(B), .Cin(Cin), .Sum(Sum), .Cout(Cout)
    );

    initial begin
        Cin = 0;

        A = 4'd5;  B = 4'd3;  #10;   // 5 + 3 = 8, no overflow
        $display("5 + 3 = %0d (Cout=%b)", Sum, Cout);

        A = 4'd15; B = 4'd1;  #10;   // 15 + 1 = 16 -> overflows a 4-bit result!
        $display("15 + 1 = %0d (Cout=%b)", Sum, Cout);

        $finish;
    end
endmodule

Why the second result "looks wrong" at first glance
15 + 1 truly equals 16 — but a 4-bit Sum bus can only represent 0–15. The 5th bit of the true answer (the "16") has nowhere to go inside a 4-bit bus, so it appears on Cout instead. This is exactly why real multi-bit adders in processors chain Cout into a wider result or into the next adder stage — losing track of this bit is a classic source of silent arithmetic bugs.

Common Mistakes

  • Forgetting that Cout must be captured somewhere — silently ignoring it causes incorrect results for any addition that overflows the bus width.
  • Connecting the wrong Cin at the very first adder stage — it must be tied to 0 (or an actual incoming carry) rather than left floating.
  • Using decimal literals without specifying width/base (e.g., writing 5 instead of 4'd5) — usually fine for small values, but can cause subtle width-mismatch bugs in larger expressions.
  • Forgetting to declare loop variables (integer i;) outside the initial block in some simulators.

Summary

The half adder and full adder from Chapter 4 translate directly into dataflow, behavioral, and structural Verilog, and every version can (and should) be verified with a testbench sweeping all input combinations. Testing Chapter 11's generate-based ripple-carry adder with real numbers — including a deliberately overflowing case — demonstrates exactly why Cout must never be ignored in real multi-bit arithmetic.

Interview Questions

  • How would you verify a full adder using a testbench with minimal code?
    Use a for loop with the concatenation operator to sweep a single loop counter across all 8 possible 3-bit input combinations ({a,b,cin} = i[2:0]), rather than writing out each combination manually.
  • What happens if Cout is ignored in a multi-bit adder design?
    Any addition whose true result exceeds the bus width will silently wrap around (lose its most significant bit), producing an incorrect result with no indication of the error unless Cout is checked.

Viva Questions

  • What does {a, b, cin} = i[2:0] do in the full adder testbench?
    It uses concatenation to pack the 3 lowest bits of the loop counter i directly into a, b, and cin, automatically sweeping through all 8 input combinations.
  • For a 4-bit ripple adder, what is the maximum representable Sum value before overflow?
    15 (4'b1111) — anything beyond that sets Cout to indicate overflow.
