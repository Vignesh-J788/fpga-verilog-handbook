Combinational Circuits

You now know gates and simplification. This chapter shows what happens when you wire gates together into real, useful building blocks — adders, multiplexers, decoders — the same blocks you'll later write in actual Verilog code in Part 5.

📖 Beginner Level🕐 —🧩 9 sections

What Makes a Circuit "Combinational"?

A combinational circuit is any circuit whose output depends only on the current inputs, at this exact instant — nothing about what happened a second ago matters. Feed it the same inputs a thousand times, in any order, at any time, and you get the exact same output every single time. There is no memory involved anywhere.

Analogy · A Calculator Button

Press 7 then + then 3 on a basic calculator, and it shows 10. It doesn't matter if you did this at 9am or 9pm, or if you'd done a completely different calculation five minutes earlier — the answer to 7+3 is always 10, right now, based only on the buttons pressed right now. That's a combinational circuit's entire personality: no history, no memory, just "given this input, right now, here's the output."

This is different from a sequential circuit (Chapter 5), where the output can depend on the past — like a counter that remembers what number it was on before increasing it further. We'll draw that contrast properly in the next chapter; for now, just remember: combinational = no memory, purely input → output, instantly.

The Standard Design Procedure

Every combinational circuit in this chapter — and every one you'll ever design — is built using the exact same four-step recipe:

  1. Understand the problem and state clearly what output is needed for which input conditions.
  2. Build the truth table — list every possible input combination and the required output for each.
  3. Derive the Boolean expression — either directly, or by simplifying with Boolean algebra (Chapter 2) or a Karnaugh Map (Chapter 3).
  4. Draw the gate-level circuit from the simplified expression.

We'll follow exactly these four steps for the half adder and full adder below, so you can see the whole recipe in action, not just the final answer.

The Half Adder

Step 1 — The problem: we want a circuit that adds two single binary digits, A and B, and produces a Sum and a Carry (the "carry" is exactly like the carry-over you learned in primary school addition — when 1+1 makes a 2, which can't fit in one binary digit, so it carries into the next column).

Step 2 — Truth table:

ABSumCarry
0000
0110
1010
1101

Step 3 — Boolean expressions: looking at the Sum column, it's 1 exactly when A and B disagree — that's the exact definition of XOR from Chapter 2. The Carry column is 1 only when both are 1 — that's AND.

Sum = A ⊕ B     Carry = A · B

Step 4 — Circuit:

The limitation
A half adder can only add two single bits with no incoming carry from a previous column. Real multi-bit addition needs to also accept a carry coming in from the previous column — which is exactly what the full adder fixes.

The Full Adder

A full adder adds three bits: A, B, and Cin (carry-in from the previous column), producing Sum and Cout (carry-out to the next column).

ABCinSumCout
00000
00110
01010
01101
10010
10101
11001
11111
Sum = A ⊕ B ⊕ Cin     Cout = A·B + B·Cin + A·Cin

Chaining Full Adders: The Ripple Carry Adder

To add real multi-bit numbers (like two 4-bit numbers), you simply chain full adders side by side, feeding each one's Cout into the next one's Cin — exactly like carrying over digits when you add multi-digit numbers by hand on paper.

Why it's called "ripple"
Each stage must wait for the carry from the previous stage before it can produce its own final, correct output — the carry "ripples" down the chain one stage at a time. For very wide numbers (32-bit, 64-bit), this delay adds up, which is why faster (and more complex) adder designs like carry-lookahead adders exist in real high-speed processors.

Multiplexer (MUX) & Demultiplexer (DEMUX)

Analogy · The Train Platform Switch

Imagine 4 train tracks (data lines) all merging toward a single platform, but only one track's train is allowed onto the platform at a time. A switch operator (the select lines) decides which one track gets connected through right now. That's a multiplexer: many inputs, one chosen output. A demultiplexer is the exact reverse: one incoming train, and the switch operator decides which one of several outgoing tracks it gets routed onto.

Select lines follow a simple binary counting rule: for a MUX/DEMUX with n select lines, you can choose between 2ⁿ data lines. Two select lines (S1,S0) give you 4 choices (00,01,10,11) — matching the 4 data lines shown above. We'll build these fully in Verilog, gate-by-gate, in Chapter 17.

Decoder & Encoder

A decoder takes an n-bit binary code and activates exactly one of 2ⁿ output lines — the one matching that code. A common example is a 2-to-4 decoder: 2 input bits select which single one of 4 output lines turns on.

Analogy · Hotel Room Key Card

Your key card carries a binary code. The door lock system "decodes" that code and unlocks exactly one door — yours — leaving every other door untouched. That's a decoder: one matching code in, exactly one output activated.

An encoder does the reverse job: it looks at several input lines (only one of which is expected to be active at a time) and outputs the binary code representing which input was active. A priority encoder is a smarter version that also handles the case where more than one input is active at once, by picking whichever has the highest "priority" — we cover this in full detail with real Verilog code in Chapter 18.

Finally, a quick preview: a comparator is another common combinational block that takes two binary numbers and reports whether A>B, A=B, or A<B — we build this fully, with cascading multi-bit comparison, in Chapter 19.

Summary

A combinational circuit's output depends only on its current inputs, with zero memory of the past. Every design follows the same recipe: state the problem, build the truth table, derive and simplify the Boolean expression, then draw the gate circuit. The half adder (XOR for Sum, AND for Carry) is the simplest building block; the full adder extends it to handle a carry-in, and chaining full adders together (ripple-carry) builds real multi-bit adders. Multiplexers route many inputs to one output; demultiplexers do the reverse; decoders activate exactly one output line matching a binary code; encoders report the code of whichever single input is active.

Key Points

  • Combinational = no memory, output = f(current inputs) only.
  • Half Adder: Sum = A⊕B, Carry = A·B.
  • Full Adder: Sum = A⊕B⊕Cin, Cout = AB + BCin + ACin — buildable from 2 half adders + 1 OR gate.
  • n select lines → 2ⁿ choices, for both MUX and DEMUX.
  • Decoder: code in → one-of-many output activated. Encoder: one active input → code out.
Memory Trick: "Half adder has half the job (no carry-in). Full adder does the FULL job (handles carry-in too)." For MUX/DEMUX: "MUX = Many to One, DEMUX = One to Many."

Interview Questions

  • Why can't a half adder be used directly for multi-bit addition?
    Because it has no Cin input, so it cannot accept a carry from a previous column — only the very first (least significant) bit position could ever use one alone.
  • What's the practical drawback of a ripple-carry adder?
    Each stage must wait for the previous stage's carry-out before its own output is valid, so total delay grows with the number of bits — this becomes a real speed bottleneck for wide (32/64-bit) adders.
  • Differentiate between a decoder and a demultiplexer.
    Structurally they're nearly identical, but a decoder has no separate data input — its select lines alone determine which output is activated (usually tied HIGH via an enable). A demultiplexer has an explicit data input that gets routed to the output chosen by the select lines.

Viva Questions

  • What is the Sum expression for a full adder?
    Sum = A ⊕ B ⊕ Cin
  • How many outputs does a 2-to-4 decoder have, and how many are active at once?
    4 outputs total; exactly 1 is active (HIGH) at any given time.
  • What determines how many data lines a MUX can select between?
    The number of select lines, n — giving 2ⁿ possible data lines.

2) 3 select lines (2³ = 8).
