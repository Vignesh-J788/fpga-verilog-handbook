Multiplexer & Demultiplexer

Full theory in Chapter 4. Here: a 2:1 MUX, a 4:1 MUX (two different ways to write it — one of which will genuinely surprise you), a 1:4 DEMUX, and complete testbenches for each.

📖 Beginner Level🕐 —🧩 6 sections

Quick Recap (Full Theory in Chapter 4)

A multiplexer (MUX) routes one of several data inputs through to a single output, chosen by select lines. A demultiplexer (DEMUX) does the reverse: routes one input to one of several outputs, chosen by select lines. n select lines give you 2ⁿ choices.

2:1 Multiplexer

mux2to1.v — dataflow (ternary operator, Chapter 10)
module mux2to1 (
    input  wire a, b, sel,
    output wire y
);
    assign y = sel ? b : a;
endmodule

4:1 Multiplexer — Two Different Ways to Write It

The "traditional" way uses case, exactly as you'd expect:

mux4to1_case.v
module mux4to1_case (
    input  wire [3:0] in,
    input  wire [1:0] sel,
    output reg  y
);
    always @(*) begin
        case (sel)
            2'b00: y = in[0];
            2'b01: y = in[1];
            2'b10: y = in[2];
            2'b11: y = in[3];
            default: y = 1'b0;
        endcase
    end
endmodule
A genuinely surprising shortcut
Verilog allows variable (dynamic) bit-selection — meaning sel itself can be used directly as an index into in. The entire 4:1 MUX above collapses to one line:
mux4to1_dataflow.v — the ENTIRE mux in one line
module mux4to1_dataflow (
    input  wire [3:0] in,
    input  wire [1:0] sel,
    output wire y
);
    assign y = in[sel];   // sel directly indexes into in — this IS a complete 4:1 mux
endmodule

Both versions synthesize to functionally identical hardware — this is a great example of dataflow modeling (Chapter 14) genuinely outshining behavioral modeling for a simple, regular pattern like this one.

4:1 MUX Testbench

mux4to1_tb.v
module mux4to1_tb;
    reg [3:0] in;
    reg [1:0] sel;
    wire      y;

    mux4to1_dataflow uut (.in(in), .sel(sel), .y(y));

    initial begin
        in = 4'b1010;   // in[3]=1, in[2]=0, in[1]=1, in[0]=0
        sel = 2'b00; #10;  // expect y = in[0] = 0
        sel = 2'b01; #10;  // expect y = in[1] = 1
        sel = 2'b10; #10;  // expect y = in[2] = 0
        sel = 2'b11; #10;  // expect y = in[3] = 1
        $finish;
    end

    initial $monitor("t=%0t sel=%b -> y=%b", $time, sel, y);
endmodule
selExpected y (from in=4'b1010)
000 (in[0])
011 (in[1])
100 (in[2])
111 (in[3])

1:4 Demultiplexer

demux1to4.v
module demux1to4 (
    input  wire in,
    input  wire [1:0] sel,
    output reg  [3:0] out
);
    always @(*) begin
        out = 4'b0000;         // default: every output LOW
        case (sel)
            2'b00: out[0] = in;
            2'b01: out[1] = in;
            2'b10: out[2] = in;
            2'b11: out[3] = in;
        endcase
    end
endmodule
Why the default line matters here specifically
Setting out = 4'b0000; before the case statement guarantees every unselected output line is cleanly driven LOW, not left dangling. Without it, only the selected bit of out would ever be assigned, forcing the tool to insert latches for the other three bits (Chapter 11's default-case warning, applied to partial bus assignment).
demux1to4_tb.v
module demux1to4_tb;
    regin;
    reg [1:0] sel;
    wire [3:0] out;

    demux1to4 uut (.in(in), .sel(sel), .out(out));

    initial begin
        in = 1;
        sel = 2'b00; #10;   // expect out = 0001
        sel = 2'b01; #10;   // expect out = 0010
        sel = 2'b10; #10;   // expect out = 0100
        sel = 2'b11; #10;   // expect out = 1000
        $finish;
    end

    initial $monitor("t=%0t sel=%b -> out=%b", $time, sel, out);
endmodule

Common Mistakes

  • Forgetting the default clear (out = 0) before a case that only assigns individual bits of a bus — leads to unintended latches.
  • Off-by-one mismatches between select-line width and the number of data lines (2 select lines only ever address 4 lines — 3 select lines are needed for 8).
  • Assuming dynamic bit-select indexing (in[sel]) works for indexing into unrelated separate signals — it only works on an actual vector/bus, not on several individually-declared wires.

Summary

A 4:1 MUX can be written explicitly with a case statement, or, far more compactly, using Verilog's dynamic bit-selection (in[sel]) — both produce identical hardware. A DEMUX is the reverse pattern, and must explicitly default its unselected outputs to avoid unintended latches. Both circuits are easy and fast to fully verify with a small testbench sweeping every select value.

Interview Questions

  • Why does `assign y = in[sel];` work as a complete multiplexer?
    Verilog supports dynamic (variable) bit-selection, so `sel` can act as a runtime index into the `in` bus — this is functionally identical to explicitly selecting one of several inputs with a case statement, just far more compact.
  • Why must a DEMUX's unselected outputs be explicitly defaulted?
    Because within the case statement only one bit of the output bus is assigned per branch — without an explicit default clearing the whole bus first, the unassigned bits would need to "remember" their previous value, forcing the synthesis tool to infer unintended latches.

Viva Questions

  • How many select lines does an 8:1 MUX need?
    3 (2³ = 8).
  • What line in demux1to4 prevents unintended latches?
    out = 4'b0000; placed before the case statement.

Exercises

1. Extend mux4to1 into an 8:1 MUX using both the case style and the dynamic bit-select style, and confirm they match via testbench. 2. Write demux1to8 (1-to-8 demultiplexer) with a proper default. 3. Combine a 4:1 MUX and a 1:4 DEMUX into a single "shared bus" testbench, sending a value through the MUX, then through the DEMUX, and verifying it arrives at the correct final output line.
