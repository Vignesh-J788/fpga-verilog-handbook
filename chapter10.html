always Blocks, initial Blocks & Operators

assign alone can't describe a flip-flop, an if/else decision, or a testbench stimulus. This chapter introduces the procedural blocks that unlock all of that — including your very first real flip-flop in code.

📖 Beginner Level🕐 —🧩 7 sections

The always Block — Verilog's "Whenever This Happens, Do This"

An always block describes a chunk of behavior that re-runs every time something in its sensitivity list changes. The sensitivity list is written in parentheses right after always, and tells Verilog exactly what to "listen" for.

verilog · always block anatomy
always @(sensitivity_list) begin
    // statements that run whenever the sensitivity list changes
end

There are two dramatically different "flavors" of always block, and which one you write determines whether you get plain combinational logic (Chapter 4) or real clocked memory (Chapter 5):

Flavor 1: Combinational Logic with always @(*)

Writing always @(*) tells Verilog: "re-run this block automatically whenever any signal read inside it changes." The * is shorthand that saves you from manually listing every single input — an enormous relief once your logic has many inputs. This describes plain combinational logic — exactly like Chapter 4's circuits, just written using if/else instead of an assign equation.

mux2to1.v — a 2:1 multiplexer (recall Chapter 4)
module mux2to1 (
    input  wire a,
    input  wire b,
    input  wire sel,
    output reg  y
);

    always @(*) begin
        if (sel)
            y = b;   // sel=1 -> route b through
        else
            y = a;   // sel=0 -> route a through
    end

endmodule
Why is y declared as reg here, if there's no memory?
This is exactly the trap flagged in Chapter 9: any signal assigned inside any procedural block (always or initial) must be declared reg, purely as a language rule — it says nothing about whether real memory hardware gets built. Because this always @(*) block covers every possible input combination (the if/else has no missing case) and reacts to every input change instantly, the synthesis tool builds this as plain combinational logic, with zero actual flip-flops — functionally identical to writing it with assign.

Flavor 2: Real Memory with always @(posedge clk)

Now for the genuinely exciting part. Writing always @(posedge clk) tells Verilog: "run this block only at the exact instant the clock signal rises from 0 to 1 (Chapter 5's rising edge) — ignore everything else, the rest of the time." This is how you describe real, clocked, edge-triggered memory — an actual flip-flop, synthesized as real hardware.

d_ff.v — your first real flip-flop in Verilog
module d_ff (
    input  wire clk,
    input  wire d,
    output reg  q
);

    always @(posedge clk) begin
        q <= d;   // on every rising clock edge, q copies d
    end

endmodule

Compare this directly to Chapter 5's D flip-flop theory: q only ever updates at a rising clock edge, exactly matching the edge-triggered timing diagram you saw there. Between clock edges, q holds — remembers — its last value, with zero further changes, no matter what d does in the meantime.

The single most important pattern in this handbook
always @(*) → combinational logic (no real memory). always @(posedge clk) → real clocked memory (a genuine flip-flop). You will use this exact pattern, over and over, for nearly every sequential circuit in Part 5 (counters, registers, shift registers).

A Quick Preview: = vs <=

You may have noticed the mux used = (called blocking assignment) while the flip-flop used <= (called non-blocking assignment). This distinction genuinely matters and causes real bugs when mixed up carelessly — so much so that it earns its own full chapter (Chapter 13). For now, follow this simple, safe rule: use = inside combinational (always @(*)) blocks, and <= inside clocked (always @(posedge clk)) blocks. Following this one rule will keep you safe until Chapter 13 explains exactly why it matters.

The initial Block — For Simulation, Not Real Hardware

An initial block runs its statements exactly once, starting at the very beginning of simulation time (time 0) — and then never again. Critically: initial blocks are not synthesizable — you cannot build real FPGA hardware from one. Their entire purpose is to set up test stimulus in a testbench (Chapter 12), such as feeding a sequence of input values into the circuit you're testing.

verilog · initial block example (testbench stimulus)
initial begin
    a = 0; b = 0;      // at time 0: set both inputs low
    #10 a = 1;         // at time 10: raise a
    #10 b = 1;         // at time 20: raise b
    #10 $finish;        // at time 30: end simulation
end

The #10 is a delay — "wait 10 simulation time units before continuing." This has no physical meaning on real hardware; it only exists to control the pace of a simulation. We'll use exactly this pattern to build real testbenches in Chapter 12.

The gotcha nearly every beginner hits at least once
& and && look similar but behave completely differently! & is bitwise AND — it operates on every bit independently, so 4'b1100 & 4'b1010 gives 4'b1000. && is logical AND — it treats each whole operand as one single true/false value (any nonzero value = true), so 4'b1100 && 4'b1010 just gives 1 (true AND true). Mixing these up silently produces very different — and very confusing — results.

The ternary operator is worth a special callout, because it lets you rewrite the entire mux example above as a single line:

verilog · mux rewritten with the ternary operator
assign y = sel ? b : a;   // if sel is 1, y=b; otherwise y=a

Summary

An always @(*) block, written to cover every case, synthesizes as combinational logic — no real memory, despite using reg. An always @(posedge clk) block synthesizes as real, edge-triggered memory — an actual flip-flop. Use blocking assignment (=) in combinational blocks and non-blocking assignment (<=) in clocked blocks (full reasoning in Chapter 13). An initial block runs once at simulation start and is used purely for testbench stimulus — it is never synthesizable. Verilog's operator set closely mirrors C's, with the crucial exception that bitwise (&) and logical (&&) operators mean genuinely different things.

Key Points

  • always @(*) → combinational logic. always @(posedge clk) → real clocked memory.
  • Use = in combinational always blocks, <= in clocked always blocks.
  • initial blocks run once, only in simulation — never synthesizable.
  • Bitwise (& | ~ ^) operate per-bit; logical (&& || !) treat the whole operand as one true/false value.
  • Ternary ? : is a compact inline if/else, usable directly inside assign.
Memory Trick: "Star (*) means 'watch everything, react instantly' — combinational. posedge means 'only on the tick' — real memory." For operators: "One symbol (&) touches every bit. Two symbols (&&) only care about true or false."

Interview Questions

  • What determines whether an always block synthesizes to combinational logic or a flip-flop?
    The sensitivity list and coding style: `always @(*)` with every input covered and no clock reference synthesizes as combinational logic, while `always @(posedge clk)` (or another clock edge) synthesizes as real edge-triggered memory (a flip-flop or register).
  • Why is `reg` a misleading keyword name for beginners?
    Because it sounds like it always means "register" (hardware memory), but it's actually just the required Verilog keyword for any signal assigned inside a procedural block — whether real memory gets synthesized depends entirely on how that block is written, not the reg declaration itself.
  • Why are initial blocks not synthesizable?
    They describe a one-time sequence of events tied to simulation time (using constructs like time delays, #10), which has no equivalent physical meaning in real hardware — real circuits don't have a "simulation clock" ticking independently of the actual clock signal.

Viva Questions

  • What does the `*` mean inside `always @(*)`?
    It automatically includes every signal read inside the block in the sensitivity list, so the block re-runs whenever any of them changes.
  • Which assignment operator is used inside a clocked always block, `=` or `<=`?
    `<=` (non-blocking assignment).
  • How many times does an initial block's body execute?
    Exactly once, starting at simulation time 0.
