FPGA Internal Architecture (LUT, CLB, Routing)

Time to open the black box. This chapter shows exactly what's physically sitting inside an FPGA — the LUTs that become your gates, the CLBs that bundle them with memory, and the programmable routing web that wires it all together.

📖 Intermediate Level🕐 —🧩 8 sections

The LUT — The Real Secret Behind "Reconfigurable"

Here's the single most important idea in this entire chapter: an FPGA doesn't actually contain reconfigurable AND/OR/XOR gates at all. Instead, it contains thousands of tiny memory tables called LUTs (Look-Up Tables), and each LUT can be configured to behave like any logic function you want, of a few inputs.

Analogy · A Phonebook, Not a Calculator

Imagine, instead of a person actually calculating "2+2" every time, they just flip open a phonebook to the page labeled "2,2" and read out whatever answer is written there. If someone had written "4" on that page, it behaves like an adder. If someone had written "0" on that page instead, it would behave completely differently — same phonebook-flipping mechanism, totally different behavior, just by changing what's written on the pages. A LUT is exactly this: a tiny table of pre-written answers, and your inputs simply select which answer to read out.

Concretely: a LUT with k inputs contains 2ᵏ memory cells — one answer stored for every possible input combination. The inputs act as an address that picks out one cell to read.

The powerful consequence
Rewrite those same 4 memory cells differently, and that identical piece of hardware instantly becomes an OR gate, an XOR gate, or literally any possible function of 2 inputs — without changing a single wire. This is the actual mechanism behind "reconfigurable." It's not that the gates rewire themselves — it's that the answer-table each one consults gets rewritten. Modern FPGAs commonly use 4-input or 6-input LUTs (16 or 64 memory cells each), letting a single LUT implement fairly complex functions on its own.

The CLB — Bundling a LUT With Memory

A single LUT alone can only do combinational logic (Chapter 4) — it has no memory. So FPGA vendors bundle each LUT together with a small set of extra pieces into a unit usually called a CLB (Configurable Logic Block) or slice: the LUT itself, a flip-flop (Chapter 5) right after it, and a small multiplexer that lets you choose whether the final output comes straight from the LUT (pure combinational) or from the flip-flop (registered/clocked) instead.

Real FPGA CLBs are usually more elaborate — bundling several LUTs and flip-flops per slice, plus small dedicated carry-chain hardware to make adders (Chapter 4) run faster than if they were built from plain LUTs alone. But the core idea — LUT for logic, flip-flop for memory, mux to choose — stays true across every FPGA vendor and generation.

Programmable Routing — Wiring It All Together

Thousands of CLBs are useless in isolation — they need to be connected to each other in whatever pattern your specific design requires. That job belongs to the FPGA's programmable interconnect (routing) fabric: a dense mesh of wire segments running horizontally and vertically across the chip, with programmable switch points at every intersection that can be configured to connect (or not connect) any two crossing wires.

Analogy · A City Grid With Smart Traffic Lights

Picture a city laid out in a perfect grid of streets, with a traffic control box at every intersection that can either let cars pass straight through, turn, or block the path entirely — reconfigured on demand. Your design's connections are like delivery routes: the routing fabric decides, intersection by intersection, exactly which streets get "opened" to carry your specific signals from one CLB to another, while every other unused street stays closed off.

This is why FPGA design tools (Vivado, Chapter 24) spend so much time on place and route — deciding exactly which physical CLBs your logic lands on, and exactly which switch points get turned on to connect them, all while trying to keep wire paths short enough to hit your target clock speed.

I/O Blocks — The Chip's Doorways to the Outside World

Around the outer edge of the FPGA's logic grid sit I/O Blocks (IOBs) — the circuitry directly connected to the physical metal pins of the chip package. Each IOB can be configured for a specific voltage standard, direction (input, output, or bidirectional), and drive strength, letting the same FPGA pin connect to anything from a simple LED to a high-speed HDMI link, just by configuring that IOB correctly.

Dedicated Hard Blocks — Not Everything Is Built From LUTs

Building things like multiplication or large memories purely out of general-purpose LUTs would be slow and wasteful. So modern FPGAs also include dedicated, pre-built ("hard") blocks scattered across the chip:

  • DSP Slices — dedicated hardware multipliers and adders, purpose-built for fast math (signal processing, filters, machine learning math).
  • Block RAM (BRAM) — small, fast, dedicated memory chunks distributed across the chip, far more efficient than building memory out of individual flip-flops.
  • Clock Management (PLL/MMCM) — dedicated circuitry that takes one input clock and generates other clock frequencies your design needs (faster, slower, phase-shifted), with high precision.

Putting It All Together: A Simplified Floorplan

How Your Design Actually Gets In There

Everything you just read — every LUT's memory contents, every switch point's on/off state, every CLB's mux selection — is controlled by a giant file called a bitstream. When you write Verilog code (Part 3) and run it through Vivado (Chapter 24), the tool's entire job is to figure out how to fill in every one of these millions of tiny configuration bits so the resulting hardware behaves exactly like the circuit you described — then it loads that bitstream file onto the physical board.

Summary

An FPGA's "reconfigurability" comes from LUTs — tiny memory tables that can be rewritten to represent any Boolean function of their inputs. Each LUT is bundled with a flip-flop and an output-select mux into a CLB (or slice), giving it both combinational and memory capability. Thousands of CLBs are connected via a programmable routing fabric — a grid of wires and switch points configured per-design. IOBs handle the physical connection to chip pins, while dedicated hard blocks (DSP slices, Block RAM, clock management) handle tasks too slow or wasteful to build from plain LUTs. All of this configuration — every LUT, every switch, every mux — lives inside one giant file called the bitstream.

Key Points

  • A k-input LUT stores 2ᵏ answers and can represent any function of those k inputs.
  • CLB/slice = LUT + flip-flop + output-select mux.
  • Programmable routing = grid of wires + switch points, configured per design ("place and route").
  • IOBs connect logic to physical chip pins; hard blocks (DSP, BRAM, clocking) handle specialized tasks efficiently.
  • The bitstream is the master file encoding every configuration bit on the chip.
Memory Trick: "LUT = a phonebook of pre-written answers. CLB = phonebook + memory + a switch to choose which one you get. Routing = the city's traffic lights connecting every phonebook to every other one."

Interview Questions

  • How does a LUT actually implement logic functions internally?
    It's a small memory array with 2ᵏ cells for k inputs. The inputs act as an address into this memory, and whatever value is pre-loaded at that address is the LUT's output — so any truth table can be "written into" the LUT to make it behave as that function.
  • What is the role of the routing fabric in an FPGA?
    It's a configurable mesh of wires and switch points that connects CLBs (and other blocks) together according to the specific design being implemented, allowing arbitrary signal paths across the chip.
  • Why are Block RAMs used instead of building memory from flip-flops?
    Flip-flop-based memory (built from general logic) is far less area- and power-efficient than dedicated, purpose-built RAM blocks, which are optimized specifically for dense, fast storage.
