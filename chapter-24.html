Vivado From Zero: Project → Bitstream → Board

Every line of Verilog you've written in Part 5 has been sitting in text files and simulators. This chapter is where that changes — the complete, real workflow for turning your code into a bitstream running on an actual FPGA.

📖 Intermediate Level🕐 —🧩 9 sections
A note on exact menus
Vivado's exact menu wording and icon positions shift slightly between versions. What follows describes the workflow's stable, version-independent shape — the Flow Navigator pane on the left always exposes these same stages in this same order, regardless of the exact Vivado release you're using.

What Is Vivado, Exactly?

Vivado is AMD/Xilinx's design suite — the actual software that performs everything from Chapters 13 and 7 conceptually: taking your RTL Verilog, simulating it, synthesizing it into a gate-level netlist, placing and routing that netlist onto real LUTs/CLBs, and finally packaging the result into a bitstream file ready to configure a physical chip.

Step 1: Creating a New Project

1

Launch the New Project wizard

Choose a project name and location, then select an RTL Project type — this tells Vivado you're providing your own Verilog/VHDL source, not importing an existing netlist.

2

Select your target part or board

Vivado needs to know exactly which physical chip (or development board) you're targeting, since the available LUTs, pins, and routing resources (Chapter 7) differ between chips. Pick your specific board from the board list if it's available, or the exact part number from its datasheet otherwise.

3

Finish the wizard

Vivado creates the project directory structure and opens the main IDE — the Flow Navigator pane on the left will guide you through every remaining stage described below, in order.

Step 2: Adding Design and Simulation Sources

Vivado separates your files into two categories, and mixing them up is a common beginner error:

  • Design Sources — your actual Verilog modules meant to become real hardware (everything from Part 5, minus the testbenches).
  • Simulation Sources — your testbenches (Chapter 12), which only ever run inside Vivado's simulator and are never synthesized.

Add your files through the Flow Navigator's Add Sources option, being careful to place each file in the correct category — a testbench accidentally added as a design source will cause confusing synthesis errors, since it contains non-synthesizable constructs like #10 delays (Chapter 10).

Step 3: Adding Constraints — the .xdc File

A Xilinx Design Constraints (.xdc) file tells Vivado two critical things your Verilog code alone can never express: which physical chip pin each port connects to, and what timing requirements (like clock frequency) it must satisfy.

example.xdc — mapping ports to physical board pins
# map the 'clk' port to the board's oscillator pin, with its voltage standard
set_property PACKAGE_PIN E3  [get_ports clk]
set_property IOSTANDARD LVCMOS33 [get_ports clk]

# map 'rst' to a physical push-button
set_property PACKAGE_PIN T18 [get_ports rst]
set_property IOSTANDARD LVCMOS33 [get_ports rst]

# map 'led' to a physical LED pin
set_property PACKAGE_PIN V11 [get_ports led]
set_property IOSTANDARD LVCMOS33 [get_ports led]

# declare the incoming clock's actual frequency, e.g. 100 MHz -> 10ns period
create_clock -period 10.000 -name sys_clk [get_ports clk]
Where these exact pin names come from
PACKAGE_PIN values are never guessed — they come directly from your specific board's official pinout documentation/schematic (Chapter 26 covers the Real Digital Boolean board's layout specifically). Every development board publishes a "master XDC" listing every available pin's name, exactly for this purpose.

Step 4: Running Behavioral Simulation

Before synthesizing anything, run your Chapter 12 testbenches through the Flow Navigator's Run Simulation → Run Behavioral Simulation option. This launches Vivado's own built-in simulator and waveform viewer — the same kind of waveform you've been reading since Chapter 12, just generated by the real tool now instead of described on paper.

Step 5: RTL Analysis — Viewing the Schematic

The Open Elaborated Design → Schematic option lets you see Vivado's first-pass interpretation of your Verilog as an actual gate/block diagram — a genuinely useful sanity check to confirm the tool understood your design's structure the way you intended, before spending time on full synthesis.

Step 6: Run Synthesis

Clicking Run Synthesis performs everything Chapter 13 described conceptually — converting your RTL into a real gate-level netlist of LUTs and flip-flops (Chapter 7). Afterward, check the Synthesis Completed report for:

  • Utilization — how many LUTs, flip-flops, and other resources your design consumes, out of the chip's total.
  • Warnings — often flagging exactly the kinds of issues Chapter 11 and Chapter 13 warned about, like unintended latches from incomplete case statements.

Step 7: Run Implementation

Run Implementation performs place-and-route (Chapter 7): deciding exactly which physical CLBs your synthesized logic lands on, and configuring the routing fabric's switch points to connect them. Afterward, check the Timing Summary report — this is where Chapter 13's setup time, hold time, and critical path stop being theory and become real numbers, showing whether your design actually meets its declared clock frequency (from your create_clock constraint).

What a timing failure looks like
A negative "Worst Negative Slack (WNS)" value means some path in your design is too slow for the clock frequency you declared — the fix is either optimizing your logic, reducing the declared clock frequency, or restructuring the design to shorten its critical path.

Step 8: Generate Bitstream

Once implementation succeeds, Generate Bitstream packages the fully placed-and-routed design into the final .bit file — the actual configuration data described back in Chapter 7, ready to be loaded onto real silicon.

Step 9: Programming the Real Board

1

Connect your board

Plug your FPGA board into your computer via USB (this also usually provides the JTAG programming connection).

2

Open Hardware Manager, then Open Target → Auto Connect

Vivado searches for and connects to your physical board over the USB/JTAG link.

3

Program Device

Select your generated .bit file and click Program — Vivado loads your configuration directly onto the chip's configuration memory (Chapter 7). The instant this finishes, your board is physically running the exact circuit you designed.

Summary

The complete Vivado flow mirrors everything taught conceptually in Parts 2–3 of this handbook: create an RTL project targeting your specific board, add design sources and separate simulation (testbench) sources, add an XDC file mapping ports to physical pins and declaring clock timing, simulate to verify behavior, synthesize into a gate-level netlist, implement (place and route) onto real chip resources, generate the bitstream, then program the physical board through Hardware Manager.

Key Points

  • Design sources become real hardware; simulation sources (testbenches) never do.
  • XDC files map ports to physical pins and declare clock/timing constraints.
  • Synthesis reports utilization and warnings; Implementation reports timing (WNS) and finalizes placement/routing.
  • Generate Bitstream produces the .bit file; Hardware Manager programs it onto the real board.
Memory Trick: "Sources, Constraints, Simulate, Synthesize, Implement, Bitstream, Program — SCSSIBP, the same seven steps, every single project."

Interview Questions

  • What is the purpose of an XDC constraints file?
    It maps design ports to physical chip pins (with their voltage/IO standards) and declares timing requirements like clock period, giving the synthesis and implementation tools the physical and timing context that pure RTL code cannot express on its own.
  • What is the practical difference between synthesis and implementation in Vivado?
    Synthesis converts RTL into an abstract gate-level netlist (LUTs, flip-flops, and their connections) without yet assigning physical locations. Implementation performs place-and-route, assigning that netlist to specific physical CLBs and configuring the routing fabric's switch points on the real chip.
  • What would you check first if a design fails timing after implementation?
    The Timing Summary report's Worst Negative Slack (WNS) and the specific failing path it highlights, to identify which portion of the design's critical path is too slow for the declared clock frequency.

Viva Questions

  • What file extension do Vivado constraint files use?
    .xdc
  • What does "Auto Connect" do in Hardware Manager?
    It searches for and connects Vivado to a physically attached FPGA board over USB/JTAG.
  • What file type does Generate Bitstream produce?
    A .bit file.
