Verilog Basics: module, ports, wire, reg, assign

This is the chapter where you write your first real hardware. Before any syntax, we need to fix one idea firmly in your head: Verilog is not a programming language in the way C is — it's a language for describing hardware that already exists in parallel.

📖 Beginner Level🕐 —🧩 8 sections

What Is a Hardware Description Language?

Verilog is a Hardware Description Language (HDL). That name is precise — you're not writing a sequence of steps for a processor to execute one at a time. You're describing a circuit — a structure of gates, wires, and registers that will physically exist, all operating simultaneously, the instant it's configured onto an FPGA (Chapter 7).

The single biggest mental trap for beginners coming from C
In C, code executes top to bottom, one line at a time — line 5 waits for line 4 to finish. In Verilog, most of what you write describes things that exist all at once, forever, in parallel — much closer to describing a diagram than describing a sequence of actions. Two assign statements don't happen "one after the other" — they're both just permanently true statements about how two different wires behave, like two separate physical wires sitting on a breadboard at the same time. We'll come back to this contrast constantly, because it's the #1 source of beginner bugs.

module and endmodule — The Basic Container

Every single piece of hardware you describe in Verilog lives inside a module. Think of a module as a labeled black box: it has a name, a defined set of connection points (called ports), and, inside, a description of exactly what it does. Every module you write must start with the keyword module and end with endmodule — no exceptions, ever.

Analogy · A Labeled Kitchen Appliance

Think of a module like a blender: it has a name ("Blender"), clearly labeled sockets on the outside (power cord in, blended smoothie out), and internal machinery you don't need to see from the outside to use it. In Verilog, the module's name and its ports are the labeled sockets; everything between module and endmodule is the internal machinery.

verilog · empty module skeleton
module my_circuit (
    // ports will go here
);

    // circuit description will go here

endmodule

Ports — The Module's Connection Points

A port is one labeled wire on the outside of your module's "box" — exactly like a socket on the blender. Every port must be declared as one of three directions:

  • input — a signal coming into this module from the outside world. This module can read it, but never change it.
  • output — a signal this module sends out to the world. Other modules can read it, but never drive it themselves.
  • inout — a bidirectional port that can act as either, at different times (rare for beginners; used for things like shared data buses).
verilog · a module with ports declared
module my_circuit (
    input  wire a,
    input  wire b,
    output wire y
);

    // circuit description will go here

endmodule

Notice the ports are simply separated by commas inside the parentheses, and each one states its direction (input/output) and its type (wire, explained next).

wire vs reg — The Distinction That Confuses Everyone

This is genuinely the single most common point of confusion for every Verilog beginner, so let's be extremely precise:

wire
A wire represents a real, physical connection — like an actual copper trace. It has no memory of its own and cannot store a value; it simply, continuously reflects whatever is being driven onto it at this exact instant, by something else (usually an assign statement, or a gate).
reg
A reg is a variable that holds a value between updates — but here's the trap: a reg does NOT automatically mean a real flip-flop/memory will be built! It's simply the required keyword for anything assigned inside a procedural block (always, initial — Chapter 10). Whether real hardware memory gets built depends entirely on how you write that block, not on the keyword itself.
The simple rule for now
If you're assigning a signal using assign (outside any procedural block), it must be a wire. If you're assigning a signal inside an always block (Chapter 10), it must be declared as a reg — even if, as you'll later see, it ends up describing perfectly ordinary combinational logic with no real memory at all. This chapter only uses assign, so every signal here will be a wire.

The assign Statement — Continuous Assignment

assign creates a permanent, continuous relationship between a wire and an expression — it is always true, constantly, forever, exactly like a real physical wire connected through a gate. The moment any input on the right-hand side changes, the output updates automatically and instantly — you never need to explicitly say "now update the output."

verilog · assign syntax
assign y = a & b;   // y is continuously equal to (a AND b)

The operators you use inside an assign should look familiar from Chapter 2's Boolean algebra:

Two Full, Complete, Working Examples

Example 1: An AND Gate

Let's build the AND gate from Chapter 2 as a genuine, complete Verilog module:

and_gate.v
module and_gate (
    input  wire a,
    input  wire b,
    output wire y
);

    assign y = a & b;   // y is HIGH only when both a and b are HIGH

endmodule

That's it — that's a complete, real, synthesizable Verilog description of an AND gate. Every single line has a job: module and_gate(...) names the box and lists its sockets, and the one assign line describes its entire behavior, permanently.

Example 2: The Half Adder (from Chapter 4)

Remember the half adder's equations from Chapter 4? Sum = A⊕B and Carry = A·B. Here they are, translated directly into Verilog, almost word for word:

half_adder.v
module half_adder (
    input  wire a,
    input  wire b,
    output wire sum,
    output wire carry
);

    assign sum   = a ^ b;   // XOR -> sum bit
    assign carry = a & b;   // AND -> carry bit

endmodule
Notice something important
Both assign lines exist at the same time, permanently, in parallel — exactly like two separate real wires, each connected through its own gate. This is precisely the "everything happens simultaneously" mindset from the very start of this chapter, now shown in real, working code.

Comments and Naming Conventions

Verilog supports the same two comment styles as C, which you already know:

verilog · comments
// a single-line comment

/* a
   multi-line
   comment */

By strong convention (not a hard rule, but you should follow it): module and signal names use lowercase_with_underscores, module names describe what the circuit is (half_adder, and_gate), and port names are kept short and meaningful (a, b, sum, carry rather than vague names like x1, temp).

Summary

Verilog describes hardware, not sequential instructions — everything you write generally exists all at once, in parallel, like real physical wires. Every design lives inside a module...endmodule block, with input/output/inout ports as its connection points. A wire is a plain physical connection with no memory; a reg is a variable used inside procedural blocks (Chapter 10) that does not automatically imply real hardware memory. The assign statement creates a permanent, continuous relationship between a wire and an expression, instantly reacting to any change on its right-hand side.

Key Points

  • Verilog describes parallel hardware, not a sequential program.
  • Every design lives in module ... endmodule.
  • Ports: input, output, inout.
  • wire = plain connection, no memory. reg = procedural-block variable, does not automatically mean real memory hardware.
  • assign = permanent, continuous, instantly-reacting relationship — used only with wire.
Memory Trick: "wire = a real wire, always live. reg = just a box that remembers a value in code — real memory hardware only appears if you write it that way." And: "assign is a promise that's always kept, instantly, forever."

Interview Questions

  • What is the key conceptual difference between Verilog and a language like C?
    C describes a sequence of instructions executed one at a time by a processor. Verilog describes hardware structure and behavior — most constructs describe things that exist and operate simultaneously and continuously, not a step-by-step sequence.
  • Does declaring a signal as `reg` always mean a flip-flop will be synthesized?
    No. `reg` is simply the required keyword for signals assigned inside procedural blocks. Whether the synthesis tool builds actual memory (a flip-flop) or just combinational logic depends on how the always block is written, not the reg keyword itself.
  • What does the `assign` statement actually model in hardware?
    A permanent, continuous connection — like a real wire routed through combinational gates — that updates its output instantly whenever any input on its right-hand side changes.
