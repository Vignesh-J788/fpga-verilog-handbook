Flip-Flops: SR, D, JK, T

Chapter 5 promised full Verilog for all four flip-flop types. Here they are — plus the async-reset pattern every real design needs, and your first testbench with a real clock generator.

📖 Beginner Level🕐 —🧩 7 sections

Quick Recap (Full Theory in Chapter 5)

TypeBehavior
SRSet / Reset / Hold; S=R=1 forbidden
DQ simply copies D at the clock edge
JKLike SR, but J=K=1 toggles instead of forbidden
TToggles when T=1, holds when T=0

SR Flip-Flop

sr_ff.v
module sr_ff (
    input  wire clk, s, r,
    output reg  q
);
    always @(posedge clk) begin
        case ({s, r})
            2'b00: q <= q;     // hold
            2'b01: q <= 1'b0;   // reset
            2'b10: q <= 1'b1;   // set
            2'b11: q <= 1'bx;   // forbidden -> explicitly modeled as unknown
        endcase
    end
endmodule

Notice we explicitly write 1'bx (an unknown value) for the forbidden case, rather than silently picking some arbitrary behavior — this makes the danger visible in simulation instead of hiding it.

D Flip-Flop — Now With a Real-World Reset

Chapter 10 already gave you the basic D flip-flop. Every real design also needs a reset — a way to force known starting values into memory when the board powers on. Here's the industry-standard pattern, an asynchronous active-high reset:

d_ff_reset.v
module d_ff_reset (
    input  wire clk, rst, d,
    output reg  q
);
    always @(posedge clk or posedge rst) begin
        if (rst)
            q <= 1'b0;   // reset wins immediately, regardless of clk
        else
            q <= d;      // normal D flip-flop behavior
    end
endmodule
Why rst is inside the sensitivity list too
Listing posedge rst alongside posedge clk means this block also runs the instant rst rises — without waiting for a clock edge. This is exactly what "asynchronous" reset means: it can force q to 0 immediately, at any time, clock or no clock. A synchronous reset instead only checks rst inside a posedge clk-only block — it would wait for the next clock edge to take effect. Both are used in real designs; asynchronous reset is simpler to reason about but needs careful timing handling, which Vivado's constraints (Chapter 24) help manage.

JK Flip-Flop

jk_ff.v
module jk_ff (
    input  wire clk, j, k,
    output reg  q
);
    always @(posedge clk) begin
        case ({j, k})
            2'b00: q <= q;     // hold
            2'b01: q <= 1'b0;   // reset
            2'b10: q <= 1'b1;   // set
            2'b11: q <= ~q;    // TOGGLE -- this is JK's fix for SR's forbidden case
        endcase
    end
endmodule

T Flip-Flop

t_ff.v
module t_ff (
    input  wire clk, t,
    output reg  q
);
    always @(posedge clk) begin
        if (t)
            q <= ~q;   // toggle
        else
            q <= q;    // hold
    end
endmodule
A neat structural insight
A T flip-flop can also be built structurally from a D flip-flop, by feeding d_ff's d input with t ^ q (its own output, XORed with T): if T=0, d = 0^q = q (holds); if T=1, d = 1^q = ~q (toggles). This is exactly why T flip-flops are the natural building block for counters (Chapter 21) — each bit simply "wants to toggle."

A Combined Testbench — With Your First Real Clock Generator

Every testbench so far has manually stepped through values with #10. For clocked circuits, it's far more natural to generate a free-running clock once, and just drive the other inputs against it:

flipflops_tb.v
module flipflops_tb;
    reg clk = 0, rst = 0, d = 0, j = 0, k = 0, t = 0;
    wire q_d, q_jk, q_t;

    // free-running clock: flips every 5 time units -> 10-unit period
    always #5 clk = ~clk;

    d_ff_reset dut_d  (.clk(clk), .rst(rst), .d(d), .q(q_d));
    jk_ff      dut_jk (.clk(clk), .j(j), .k(k), .q(q_jk));
    t_ff       dut_t  (.clk(clk), .t(t), .q(q_t));

    initial begin
        rst = 1; #12 rst = 0;   // hold reset through the first clock edge, then release

        d = 1; j = 1; k = 1; t = 1;  // J=K=1 -> jk toggles. T=1 -> t toggles every edge.
        #100;
        $finish;
    end

    initial $monitor("t=%0t clk=%b rst=%b | q_d=%b q_jk=%b q_t=%b", $time, clk, rst, q_d, q_jk, q_t);
endmodule
Reading the always #5 clk = ~clk; pattern
This tiny always block (no sensitivity list at all — it just keeps re-triggering itself) is the standard way to generate a free-running clock in simulation: wait 5 time units, flip clk, forever. You'll reuse this exact pattern in every remaining testbench in this handbook.

Expected behavior: q_d starts at 0 (held there by reset), then follows d once rst releases. q_jk toggles every clock edge once J=K=1. q_t also toggles every clock edge once T=1 — and if you compare their waveforms, q_jk and q_t should be identical, since both are just "toggle on every edge" in this test.

Common Mistakes

  • Using = instead of <= inside any of these clocked blocks — always non-blocking (Chapter 13).
  • Forgetting to include the reset in the sensitivity list for an asynchronous reset design (@(posedge clk or posedge rst)) — omitting it makes the reset synchronous instead, changing its timing behavior.
  • Leaving SR's forbidden state silently unhandled — always make the invalid case explicit (even just to flag it), rather than letting simulation quietly guess.
  • Forgetting to initialize testbench registers (like clk, d) — an uninitialized reg starts as x (unknown) in simulation, which can make early waveform output confusing.

Summary

All four flip-flop types share the same always @(posedge clk) skeleton, differing only in their internal case/if logic: SR (set/reset/hold/forbidden), D (simple copy), JK (SR with toggle instead of forbidden), and T (toggle/hold). Real designs add an asynchronous or synchronous reset for known startup behavior. Testbenches for clocked circuits typically use a free-running clock generator (always #5 clk = ~clk;) rather than manually stepping through time.

Interview Questions

  • What is the difference between synchronous and asynchronous reset in Verilog?
    An asynchronous reset appears in the always block's sensitivity list (e.g., `posedge rst`) and takes effect immediately, independent of the clock. A synchronous reset is only checked inside a clock-edge-triggered block, so it only takes effect on the next active clock edge.
  • How does a JK flip-flop improve on an SR flip-flop?
    It replaces SR's forbidden/undefined S=R=1 case with a well-defined toggle behavior when J=K=1, eliminating the invalid state entirely.
  • Why is `always #5 clk = ~clk;` used in testbenches?
    It's a compact, standard way to generate a free-running simulation clock, alternating clk every 5 time units to produce a steady clock period, without needing to manually toggle it throughout the stimulus.

Viva Questions

  • What does a T flip-flop do when T=0?
    It holds its current value — no change.
  • Which flip-flop simply copies its input to its output on every clock edge?
    The D flip-flop.
  • What value does the SR flip-flop code assign to q for S=R=1?
    1'bx — an explicitly unknown/undefined value.
