Blocking vs Non-blocking, Synthesis vs RTL vs Timing

We promised back in Chapter 10 that = vs <= genuinely matters. Here's the full explanation — plus the concepts (RTL, synthesis, timing) that connect everything you've written in Part 3 to the real silicon from Part 2.

📖 Intermediate Level🕐 —🧩 9 sections

Blocking Assignment (=)

A blocking assignment executes immediately and completely before the next statement in the same block even begins — exactly like ordinary C code, top to bottom, one at a time. Each statement "blocks" the next one from starting until it's finished.

verilog · blocking assignment, order matters
always @(*) begin
    temp = a & b;   // step 1: temp is computed and updated FIRST
    y    = temp | c;   // step 2: this line sees the NEW temp from step 1
end

This sequential, "each line finishes before the next starts" behavior is exactly what you want for combinational logic, where one signal's value often genuinely depends on another signal computed earlier in the same block.

Non-blocking Assignment (<=)

A non-blocking assignment works completely differently: every right-hand side in the block is evaluated first, using the values that existed before the block started running — and only after every line has been evaluated do all the updates get applied, simultaneously, at the very end of that time step.

Why this genuinely matters
This is exactly how real flip-flops behave in physical hardware: every flip-flop in a design samples its input at the exact same clock edge, using whatever value existed the instant before that edge — none of them can "see" another flip-flop's brand new value early. Non-blocking assignment is Verilog's way of faithfully modeling that genuine hardware parallelism (Chapter 5's edge-triggered behavior).

The Classic Example That Makes It Click: Swapping Two Registers

Nothing explains this distinction better than trying to swap two flip-flops' values on a clock edge. Watch what happens with each assignment type:

Using = (blocking) — BROKEN swap
always @(posedge clk) begin
    a = b;   // a immediately becomes b
    b = a;   // but a is ALREADY b now!
end

Line 2 sees the already-updated a (which is now equal to b), so b just gets set to itself. Result: both a and b end up equal to the original b — the swap silently fails.

Using <= (non-blocking) — CORRECT swap
always @(posedge clk) begin
    a <= b;   // scheduled: uses OLD b
    b <= a;   // scheduled: uses OLD a
end

Both right-hand sides are read using their original values before either update is applied, and then both updates happen together. Result: a correctly becomes the old b, and b correctly becomes the old a — a genuine swap, in a single clock edge.

The Industry-Standard Rule (Follow This Always)

Memorize this pairing
  • Inside always @(*) (combinational logic) → always use = (blocking).
  • Inside always @(posedge clk) (sequential/clocked logic) → always use <= (non-blocking).
  • Never mix both assignment types on the same signal, and avoid mixing them within the same always block in general.

Every single sequential example from Chapters 10 and 11 (the D flip-flop, the T flip-flop) already followed this rule correctly — now you know exactly why.

What Is RTL (Register Transfer Level)?

Everything you've written in Part 3 exists at a level of abstraction called RTL — Register Transfer Level. RTL describes a design in terms of registers (the flip-flops/memory holding state, Chapter 5) and the combinational logic that transfers/transforms data between them on each clock cycle. You never had to describe individual transistors or even individual gates — you described behavior ("on a clock edge, q becomes d"; "y is always a AND b"), and left the exact gate-level implementation to a tool.

What Is Synthesis?

Synthesis is the automated process that takes your RTL Verilog code and converts it into an actual gate-level netlist — a real, specific list of LUTs, flip-flops, and interconnections (Chapter 7) that will physically implement your described behavior on the target FPGA. This is the single most important translation step in the entire flow: it's how "q <= d;" written in a text file becomes a real, physical flip-flop wired into silicon.

Simulation ≠ Synthesis — a warning worth remembering
Code that behaves correctly in simulation isn't automatically guaranteed to synthesize into the hardware you expect. Common traps: an incomplete if/case with no default (Chapter 11) accidentally infers a latch; using non-synthesizable constructs (like #10 delays or $display) inside code meant for real hardware, rather than a testbench; or relying on simulation-only initial values for registers that real hardware won't have. This is exactly why Vivado (Chapter 24) provides both a simulator and a separate synthesis step — and why professional teams always check both.

Timing: Setup Time, Hold Time, and the Critical Path

Once your design is real hardware, a new, very physical question appears: how fast can the clock actually tick before things start failing? Answering this requires three timing concepts:

  • Propagation delay — the real, physical time combinational logic takes to settle after its inputs change (nothing is truly instant in real hardware, unlike in our idealized theory chapters).
  • Setup time — a flip-flop needs its data input to be stable for a small window before the clock edge arrives, or it may capture the wrong value or an undefined result.
  • Hold time — the data input must also stay stable for a small window after the clock edge, for the same reason.
The critical path — the single number that limits your clock speed
The critical path is the slowest such route anywhere in your entire design — the one combination of clk-to-q delay + combinational delay + setup time that takes the longest. Your clock period must be at least that long, or the receiving flip-flop might sample garbage. This is precisely what Vivado's timing analysis (Chapter 24) calculates automatically, reporting your design's maximum safe clock frequency.

Summary

Blocking assignment (=) executes statements sequentially, each one finishing before the next starts — correct for combinational (always @(*)) logic. Non-blocking assignment (<=) evaluates every right-hand side using pre-block values first, then applies all updates simultaneously — correctly modeling real parallel flip-flop behavior, and essential inside clocked (always @(posedge clk)) blocks. Your RTL Verilog code describes behavior at the register/combinational-logic level; synthesis translates that RTL into a real gate-level netlist of LUTs and flip-flops. Once real, physical timing (propagation delay, setup time, hold time) determines your design's maximum safe clock frequency, governed by the slowest route through the design — the critical path.

Key Points

  • = (blocking): sequential, one line finishes before the next starts — use in combinational blocks.
  • <= (non-blocking): all RHS evaluated first with old values, updates applied together — use in clocked blocks.
  • RTL = describing a design via registers + the combinational logic between them.
  • Synthesis = converting RTL Verilog into a real gate-level netlist for the target FPGA.
  • Critical path = the slowest signal route in the design; it sets the maximum safe clock frequency.
Memory Trick: "Blocking blocks the next line until it's done — like a queue, one at a time. Non-blocking doesn't block anyone — everyone reads the old values first, then updates together, just like real flip-flops on a clock edge."

Interview Questions

  • Why should non-blocking assignment always be used for sequential (clocked) logic?
    Because it correctly models how real flip-flops behave — all of them sample their inputs using pre-edge values simultaneously, with no flip-flop able to see another's newly updated value early. Blocking assignment can create race conditions and incorrect behavior (as in the swap example) when used for this purpose.
  • What is the difference between RTL and a gate-level netlist?
    RTL describes behavior in terms of registers and the combinational logic transferring data between them, at a relatively high level of abstraction. A gate-level netlist is the fully synthesized, concrete list of actual gates/LUTs/flip-flops and their exact interconnections that implement that RTL behavior on real hardware.
  • What determines a synthesized design's maximum clock frequency?
    The critical path — the slowest route through the design, combining clock-to-output delay, combinational propagation delay, and the receiving flip-flop's setup time — must fit within one clock period; this longest path sets the upper limit on safe clock speed.
