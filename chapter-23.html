Project 1: Stopwatch (Minutes : Seconds)

A stopwatch is a counter (Chapter 21) with two twists: it counts in a 0–59 range instead of a clean power-of-two range, and it only advances on a real 1-second "tick," which in a real design would come from a clock divider exactly like Chapter 22's LED blinker.

stopwatch.v
module stopwatch (
    input  wire clk, rst, run, tick,   // tick pulses once per second, from a divider (Chapter 22)
    output reg  [5:0] seconds,
    output reg  [5:0] minutes
);
    always @(posedge clk or posedge rst) begin
        if (rst) begin
            seconds <= 0;
            minutes <= 0;
        end else if (run && tick) begin
            if (seconds == 6'd59) begin
                seconds <= 0;
                if (minutes == 6'd59)
                    minutes <= 0;         // wraps after 59:59, exactly like Chapter 16's overflow
                else
                    minutes <= minutes + 1;
            end else begin
                seconds <= seconds + 1;
            end
        end
        // if run=0, seconds/minutes simply hold -- this IS the pause behavior
    end
endmodule

Notice the seconds-to-minutes rollover (seconds == 59 → reset to 0 and bump minutes) is exactly a carry, structurally identical to a full adder's cout from Chapter 4 — just with a "carry out at 59" boundary instead of "carry out at 15."

stopwatch_tb.v
module stopwatch_tb;
    reg clk = 0, rst = 1, run = 0, tick = 0;
    wire [5:0] seconds, minutes;

    stopwatch uut (.clk(clk), .rst(rst), .run(run), .tick(tick), .seconds(seconds), .minutes(minutes));

    always #5 clk = ~clk;

    // generate one "tick" pulse every 20 time units, simulating a real 1-second divider
    always #20 tick = ~tick;

    initial begin
        #12 rst = 0;
        run = 1;
        #1000 run = 0;   // pause -- seconds/minutes should freeze here
        #100  run = 1;  // resume -- should continue from where it paused
        #1000 $finish;
    end

    initial $monitor("t=%0t run=%b -> %0d:%0d", $time, run, minutes, seconds);
endmodule

Project 2: Simple 4-Function Calculator

This project directly reuses Chapter 11's mini_alu, feeding its result straight into Chapter 19's seven_seg_decoder:

calculator.v — structural composition of two earlier chapters' modules
module calculator (
    input  wire [1:0] op,
    input  wire [3:0] a, b,
    output wire [3:0] result,
    output wire [6:0] seg
);
    mini_alu          alu  (.op(op), .a(a), .b(b), .result(result));
    seven_seg_decoder disp (.bcd(result), .seg(seg));
endmodule
A deliberate scope limit worth understanding
Chapter 19's seven-segment decoder only has entries for BCD digits 0–9. If a + b (or any operation) produces a result of 10–15, the display will simply blank (its default case). Displaying a full two-digit decimal result (like "12") on two separate seven-segment displays requires converting binary to BCD first — a genuinely useful but more advanced technique (often done with the "double dabble" algorithm) that sits just beyond this handbook's scope. For now, this calculator is correct and complete for results 0–9, and cleanly (not silently) blanks anything beyond that.

Project 3: PWM LED — Controlling Brightness, Not Just On/Off

Chapter 22's LED blinker only ever fully turns an LED on or off. But what if you want it dim — partially lit? Real LEDs can't be "half voltage" the way you'd dim an old incandescent bulb (Chapter 1's digital-only nature), so instead we use PWM (Pulse Width Modulation): switch the LED on and off extremely fast, and control what fraction of each cycle it's on. The human eye is too slow to see the flicker (exactly like Chapter 22's blinker reasoning, in reverse) and instead perceives the average brightness.

pwm_led.v
module pwm_led (
    input  wire clk, rst,
    input  wire [7:0] duty,   // 0 = always off, 255 = always on, 128 = ~50% brightness
    output reg  led
);
    reg [7:0] count;

    always @(posedge clk or posedge rst) begin
        if (rst) count <= 0;
        else        count <= count + 1;   // free-running 8-bit counter, wraps every 256 cycles
    end

    always @(*) begin
        led = (count < duty);   // LED on for exactly 'duty' out of every 256 cycles
    end
endmodule

Across every full 256-cycle sweep of count, the LED is HIGH for exactly duty of those cycles — so duty = 64 gives 25% brightness, duty = 192 gives 75%, and so on. This exact same technique (a free-running counter compared against a threshold) controls motor speed, servo position, and LED brightness in real embedded and FPGA systems everywhere.

pwm_led_tb.v
module pwm_led_tb;
    regclk = 0, rst = 1;
    reg [7:0] duty = 64;   // 25% brightness
    wire led;

    pwm_led uut (.clk(clk), .rst(rst), .duty(duty), .led(led));
    always #5 clk = ~clk;

    initial begin
        #12 rst = 0;
        #3000 $finish;   // long enough to see multiple full 256-cycle PWM periods
    end
endmodule

Project 4: Seven-Segment Digit Counter (0–9, Repeating)

Our final project reuses Chapter 21's counter idea and Chapter 19's decoder together, driving a live, continuously-counting single-digit display:

seven_seg_counter.v
module seven_seg_counter (
    input  wire clk, rst,
    output wire [6:0] seg
);
    reg [3:0] digit;

    always @(posedge clk or posedge rst) begin
        if (rst)
            digit <= 4'd0;
        else if (digit == 4'd9)
            digit <= 4'd0;    // wrap at 9, not 15 -- a "modulo-10" counter, unlike Chapter 21's power-of-2 counters
        else
            digit <= digit + 1;
    end

    seven_seg_decoder disp (.bcd(digit), .seg(seg));
endmodule

This is a modulo-10 counter — it deliberately wraps at 9 instead of the natural binary wraparound at 15, precisely because it's driving a decimal display. Comparing this to Chapter 21's plain 4-bit counter (which wraps at 15 automatically) highlights an important design lesson: not every counter should be allowed to use its full natural range — sometimes you must explicitly force an earlier wraparound to match what the rest of your system expects.

Summary — And a Look Back at Part 5

All four projects in this chapter are built almost entirely from modules you already wrote: the stopwatch reuses the counter-with-rollover pattern from adders and counters; the calculator directly instantiates the ALU and seven-segment decoder from earlier chapters; PWM reuses the free-running-counter idea from the clock divider, compared against a threshold instead of counting to a fixed limit; and the seven-segment counter combines a modulo-10 counter with the same decoder used in the calculator. This is the real payoff of modular, well-tested design (Chapter 14's structural modeling): complex projects become mostly wiring, once their pieces are individually correct.

Interview Questions

  • How does PWM control an LED's apparent brightness using only fully-on/fully-off states?
    By rapidly switching the LED on and off within each fixed-length cycle, with the fraction of "on" time (duty cycle) determining the average power delivered — human vision is too slow to perceive the individual flicker and instead perceives the time-averaged brightness.
  • Why does the stopwatch's seconds counter wrap at 59 rather than at a power-of-two boundary?
    Because it must match real-world time units (60 seconds per minute), so its wraparound point is explicitly forced with an if-condition, rather than relying on natural binary overflow, which would wrap at 63 for a 6-bit value.
  • Why is the calculator project deliberately limited to displaying results 0-9?
    Because the seven-segment decoder from Chapter 19 only defines patterns for single BCD digits; displaying two-digit results would require a binary-to-BCD conversion step (such as the double-dabble algorithm) that is beyond the scope of a single decoder module.

Viva Questions

  • What does PWM stand for?
    Pulse Width Modulation.
  • In pwm_led.v, what duty value gives 100% brightness?
    255 (the counter never reaches a value ≥ duty, so led is HIGH essentially the entire time).
  • What two earlier modules does calculator.v instantiate?
    mini_alu (Chapter 11) and seven_seg_decoder (Chapter 19).
